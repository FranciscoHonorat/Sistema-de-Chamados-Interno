# ADR 0037 — kind pra testar o chart num cluster local

**Status:** aceita

## Contexto

Um chart Helm só é confiável se for instalado de verdade. Testar apenas em staging deixa os erros aparecerem tarde.

## Decisão

- **kind** (Kubernetes in Docker), com a configuração em `infra/kind/cluster.yaml` (porta 30080 exposta só no `127.0.0.1`).
- Comandos no `makefile`: `make k8s-up` (cria o cluster, builda e carrega a imagem, instala o chart), `make k8s-test` (`helm test` + smoke test), `make k8s-deploy` (upgrade sem indisponibilidade) e `make k8s-down`.
- O script `infra/scripts/k8s.sh` aceita `IMAGE=repo:tag` pra instalar uma imagem já pronta.

## Alternativas consideradas

- **minikube**: mais pesado, com VM ou driver próprio.
- **k3d**: equivalente; o kind é o que o próprio projeto Kubernetes usa nos testes.

## Consequências

- O chart é exercitado de ponta a ponta na máquina de quem desenvolve.
- Exige Docker, `kind` e `helm` instalados, só pra quem mexe na infraestrutura.
