# ADR 0023 — pgx como driver do Postgres, com SQL escrito à mão

**Status:** aceita

## Contexto

Os repositórios usam recursos específicos do Postgres (ADR 0022) e precisam de pool de conexões e transações.

## Decisão

- Usar **pgx v5** (`github.com/jackc/pgx/v5`) com `pgxpool`, sem `database/sql` e sem ORM.
- SQL escrito à mão nos adaptadores `adapters/out/postgres`.
- Um pool por módulo, com `search_path` no schema do módulo e `DB_MAX_CONNS` configurável.
- A plataforma espera o banco ficar disponível na subida, com backoff exponencial.

## Alternativas consideradas

- **GORM**: menos SQL, mas esconde as consultas e combina mal com Event Sourcing, que não tem entidade atualizada no lugar.
- **sqlc**: gera código tipado a partir do SQL. Boa opção; ficou de fora pra não ter uma etapa de geração no build.
- **`database/sql` + `lib/pq`**: o `lib/pq` está em manutenção; o pgx é mais rápido e entende os tipos do Postgres.

## Consequências

- Controle total das consultas e dos índices.
- Cada consulta é testada nos testes de integração contra Postgres real.
- Mais código de mapeamento do que com um ORM.
