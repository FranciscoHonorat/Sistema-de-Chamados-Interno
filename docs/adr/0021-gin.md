# ADR 0021 — Gin como framework HTTP

**Status:** aceita

## Contexto

A API tem 26 rotas, com parâmetros de caminho, JSON, middlewares (autenticação, request id, métricas, segurança) e grupos por módulo.

## Decisão

Usar **Gin** (`github.com/gin-gonic/gin`) nos adaptadores HTTP de entrada e na plataforma (`internal/platform/httpserver`).

- Cada módulo registra suas rotas num grupo (`/api/employees`, `/api/tickets`).
- Os middlewares da plataforma valem pra todos; o de autenticação é por módulo.
- O Gin fica **só nos adaptadores**: os testes de arquitetura proíbem o domínio e a aplicação de importá-lo (ADR 0007).

## Alternativas consideradas

- **`net/http` puro** (com o roteador do Go 1.22+): zero dependência, mas bind de JSON e grupos de middleware dariam mais código.
- **Echo, Chi, Fiber**: equivalentes em recursos. O Gin é o mais usado e documentado.

## Consequências

- Handlers curtos: bind do corpo, chamada do caso de uso, resposta.
- Trocar de framework mexe só nos adaptadores HTTP.
